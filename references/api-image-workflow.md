# 明确授权后的 API 生图流程

仅当用户明确要求或同意使用外部 API 时读取本文件。默认内置生图失败不是切换服务、模型或计费方式的授权。

## 发现与凭据边界

1. 使用用户指定的服务、当前获授权的 provider 或环境变量；不要猜服务地址，也不要把 ChatGPT 账号令牌误当该服务的图像 API Key。
2. 用该服务的模型列表接口只读发现实际可用的图像模型。仅输出相关模型 ID 和连通结果，不输出完整凭据或请求头。
3. 模型可列出不等于图像编辑端点可用。先发一个带参考图的受控请求，确认真实产物和 alpha，再扩展其他姿态。
4. `OPENAI_API_KEY` 与 `OPENAI_BASE_URL` 只在本次调用的进程环境中传递，不写入脚本参数、任务清单、导入脚本、日志、README、仓库或永久全局环境。展示错误前遮蔽凭据。
5. 只向用户认可的服务发送需要的角色图片和创作描述，不发送聊天、预设、全部配置或其他资料。

## 调用方式

使用 `$imagegen` 提供的现成 CLI，不复制、修改系统 CLI，也不临时重写一套 SDK 生图器。CLI 位置以当前安装为准，不在本技能写死某台电脑的绝对路径。

示意命令（服务与凭据已经仅注入子进程环境；模型 ID 来自用户选择和实际发现）：

```powershell
python "$IMAGE_GEN" edit --model "$IMAGE_MODEL" `
  --image "$REFERENCE_IMAGE" --prompt-file "$PROMPT_FILE" `
  --background transparent --output-format png `
  --size 1024x1024 --quality high --out "$OUTPUT_IMAGE"
```

- 脱离参考图的纯文字生成不适合后续姿态。后续图至少携带认可的 idle 和身份参考；`--image` 可重复，用于加入配对动作的 A 帧或待修复原图。
- GPT Image 2.5 系列可按其实际接口请求透明背景。选择服务支持的准确 ID，不把服务中的别名当作所有服务共有的模型，不因旧文档描述而自动降级到别的型号。
- 公开协议参考：[图像生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[图像编辑](https://developers.openai.com/api/reference/python/resources/images/methods/edit)。第三方兼容服务的实际表现需要单独确认。
- 缺少 SDK 时优先使用已存在的运行环境，或按当前环境规范通过 uv 等隔离依赖；缓存目录权限失败属于本地准备失败，不是模型拒绝。可对本次进程指定独立的可写缓存，不修改全局配置。
- 原始 API 文件另存，最终贴图由确定性缩放与编码得到。实际输出尺寸可能不同于请求值，要读文件，不能只看请求参数。

## 分阶段推进

先拿到一张可用 idle：确认文件确实来自本请求、能解码、包含真实 alpha、背景像素透明、角色结构正确。随后按任务依赖生成其他图，配对图和修复图携带相应已认可参考。

可小批量推进独立姿态，避免首次请求尚未确认就排满全部任务。失败后根据错误判断是本地依赖、权限、协议、模型还是产物问题；保留已完成图，不重复整批。请求结果不明确或可能已经计费时，不盲目重发。

局部修复要指出具体错误、正确肢体数量和必须保留的构图；新文件确认后只替换对应槽位。若输出背景不透明，重新请求原生透明输出，不能转成绿幕/抠图流程。

## 记录与交付

只记录模型 ID、请求阶段、非敏感错误、产物路径和 alpha/尺寸等必要结果。凭据、服务专属地址和完整认证配置不进入可分享产物。

`prepare` 只创建任务清单；`build` 只整理和打包本地图片。两个命令本身均不会调用远端模型。最终酒馆助手脚本内嵌的是图片，不需要收件人填写生图 API Key。
