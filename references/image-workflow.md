# 生图与素材制作

这是借鉴 Pets 的制作方法、针对 shujuku 重新定义的流程，不调用 Pets 的上传/创建工具。

## 主图与视觉锚点

根据用户角色描述记录：物种/角色、轮廓、体型、脸与眼睛、配色、材质、固定服饰/道具、画风、禁改细节。无指定画风时选能在 64～88 px 下辨认的简洁风格，不强制像素画。

先生成或选定 idle，再以它和用户参考图作为所有衍生图的真实视觉输入。走路 B、进食 B 还应携带已认可的 A 帧，以锁定姿态、体型和道具。尽量保持视角、光照、轮廓线和体型。只有自然语言角色需求且没有参考图时，idle 可以仅靠文字；其他姿态不能只凭重复文字猜角色。

默认调用当前可用内置 `image_gen`；先加载 `$imagegen` 的实际指导。它不需要为此在脚本里放 API key。本技能 `prepare` 输出的是任务清单，不是生图执行结果。

内置工具没有返回可用产物时，明确记录“未拿到图片”，不要依据目录里任意最新文件宣称成功，也不要将其描述为已确认的安全拦截。用户明确授权外部 API 后，读取 [API 生图流程](api-image-workflow.md)；不擅自切换外部服务或模型。

## 建议生成顺序

按 manifest 的目标槽位，先复用/生成 idle；再按语义小组推进：

1. 待机表情：blink、look-left、look-right、yawn。
2. 成对动作：walk-a/b、eat-a/b；两张保持身体基线、体型和道具一致，仅改变必要的步态或口部/前肢。
3. 睡眠与业务：snore、sit-snore、working、struggle、roll。
4. 互动：shy、tickle、happy、dizzy、surprised、wave。
5. 生气连段：angry、huff、pound、knockdown，保证是同一角色连续的情绪过程。
6. 贴边三图：peek、peek-original、peek-sleepy，必须单独设计裁切。

默认每次生成一个姿态，不要求模型一次精确输出 27 格大图。若模型生成了可靠的小组图，可以确定性切出图块；先检查格数与分隔，不用整幅水平翻转导致姿态顺序倒置。完整素材通常涉及 27 个槽位和多次生图，先明确用户要全套还是局部，不以重复复制 idle 偷省动作。

## 提示词原则

`imagegen-jobs.json` 包含基础 prompt、关键姿态语义、参考图路径和目标路径。根据角色特征修订这些提示词，而不是机械照搬：

- 同一角色，单独一个完整姿态，真正透明背景，无文字/水印/标签/背景场景。
- 统一方形画布，身体尺度与脚底参考线稳定；四肢不截断。
- 风格不限像素/贴纸/毛绒/黏土/3D，但小尺寸仍需可读。
- 不生成独立的气泡、速度线、悬浮星星或巨大光效，以免作为桌宠图片一起漂浮。
- 原生 CSS 已负责呼吸、转圈、抖动、摆动和惊跳；图像重点表达姿态，不把整套位移轨迹画进图里。
- working 表示忙于工作，不是跑步；roll 是可被宿主旋转的紧凑姿态；surprised 是惊醒，不要求画离地的偏移。
- angry/huff/pound/knockdown 是四个不同的语义，不用一张怒脸复制四份。
- 动作必须适配参考解剖结构：没有手臂就用摆身、抬起已有的脚或前倾表达，不为动作添加新肢体。蜷身、跌倒等复杂姿态要逐个数肢体，不能把身体弯曲处画成额外脚。
- 先修主图身份偏差，再扩展；修某个姿态时只编辑这一张，并附原主图。明确指出多余/错误部位和必须保留的部分，修正版另存，确认后只替换该槽位；其他素材不重画。

## 透明度、尺度与存储

- 必须让生图工具直接输出带真实 alpha 通道的透明背景 PNG/WebP，保留生成的 alpha。棋盘格印在 RGB 图里不叫透明。
- 禁止绿幕、蓝幕、洋红幕或其他纯色背景的中间图；禁止色键抠除、自动背景移除或手工抠图作为生成后的补救流程。输出没有真实透明背景时，重新请求透明生成或报告失败。
- Pillow 仅用于不改变背景语义的确定性整理：裁切透明留白、等比缩放、透明补边、编码、透明度检查和拼预览；预览页面的棋盘格仅用于显示透明度，不写入角色素材。
- 保留原始生成图片，整理后的单张放在 frames。最终推荐 256×256；大图原稿另存，不要硬塞数据库设置。
- 不对每个姿态都做 tight bounding-box 放大；躺下应变矮、抬手应变高，角色身体大小应稳定。
- 内置素材的额外体型补偿不作用于自定义图；不要寄希望于宿主自动修正比例。
- 探头以原生资源布局为参照。不要套用普通全身图的自动紧裁与脚底线；优先在真实宿主四个停靠方向检查裁切。
- 使用工具实际返回的文件路径。默认生图产物通常在 CODEX_HOME 下，复制到该角色工作目录，避免项目引用临时或不持久链接。
- 不把数据库预设、聊天、密钥或全部设置发给生图服务；仅使用角色参考图和必要的创作描述。

## 更新与预览

已有皮肤只改用户指定的槽，保留 manifest 的 ID；新角色生成新 manifest/ID。局部修图后同步导入 JSON、预览与分享包，避免只改原图而交付旧版本。交付输出目录必须为新的版本目录，程序不会覆盖已存在的完整交付物。

`build` 会检查实际解码、非全透明/非全不透明、非动画源、图片键、单图和总字符预算，输出透明底总览与离线浏览器预览。这些检查不是审美或语义审核：还需看实际图片是否同一角色、配对是否跳体型、探头是否可用。

离线 preview 只是部分 CSS 和切图的简化演示，不会访问酒馆。默认不启动真实数据库任务、不改变用户皮肤；用户授权安装时才进入原生宿主查看真实拖动、点击、长按和贴边。

## 从参考 Pets 技能保留/不保留的部分

保留：先基准角色再衍生、可重复的任务清单、局部修复、像素产物与清单分开、预览与持久化分开、稳定身份用于更新。

不照搬：Pets 稳定 pet ID（本流程使用 Tavern Helper script ID）、73 帧 v2 图集、16 个注视方向、九行固定动画、ChatGPT Library、Pets 上传校验或云端创建。它们都不是 shujuku 的接口。
